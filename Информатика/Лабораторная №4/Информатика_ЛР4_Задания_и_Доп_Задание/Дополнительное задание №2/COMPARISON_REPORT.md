# Дополнительное задание №2. Сравнение ручной и библиотечной конвертации INI → YAML

## Цель и постановка задачи

Найти готовые библиотеки для десериализации INI и сериализации YAML; повторить преобразование данных из обязательного и дополнительного задания №1 при помощи этих библиотек; сравнить результаты и объяснить сходство или различие. Использовать регулярные выражения в собственном коде запрещено.

## Выбранные библиотеки

1. **configparser** — стандартный модуль Python для работы с INI-файлами. Используется `ConfigParser.read_string()` для превращения INI-текста в пары секция/ключ/значение. Настройки `interpolation=None`, `strict=True`, `optionxform=str`, `inline_comment_prefixes=None` обеспечивают сопоставимое поведение с ручным парсером: выключены подстановки, запрещены дубликаты, сохраняется регистр ключей и содержимое значений с `#`/`;`.
2. **PyYAML** — библиотека сериализации YAML. Используется `yaml.safe_dump()` с параметрами `allow_unicode=True`, `sort_keys=False`, `default_flow_style=False`, `indent=2`. Для проверки содержимого применяется `yaml.safe_load()`.

Ссылки: https://docs.python.org/3/library/configparser.html ; https://pyyaml.org/wiki/PyYAMLDocumentation ; https://pypi.org/project/PyYAML/

## Алгоритм

1. Программа читает один и тот же файл `schedule.ini`.
2. Ручной путь: `parse_ini(text)` → словарь Python → `serialize_yaml(data)` → `schedule_manual.yaml`.
3. Библиотечный путь: `parse_ini_library(text)` на `configparser` → словарь Python → `serialize_yaml_library(data)` на `PyYAML` → `schedule_library.yaml`.
4. Два словаря сравниваются через `==`. Два YAML-документа также сравниваются по **восстановленным данным** (`yaml.safe_load()`), а не только по тексту.
5. Оба YAML-файла сохраняются для отчёта.

## Объяснение результатов

**Сходство данных.** Оба INI-парсера создают одинаковое представление `dict[str, dict[str, str]]`: названия секций становятся ключами внешнего словаря; ключи и значения из каждой секции помещаются во внутренний словарь. Значения остаются строками, включая время `08:10` и аудитории `1327`.

**Различие оформления YAML.** Ручной сериализатор всегда пишет строки в двойных кавычках: `"room": "1327"`. PyYAML автоматически выбирает допустимую форму представления: например, может записать `subject: Информатика`, а неоднозначные строки заключить в кавычки, например `room: '1327'`. Поэтому текст YAML-файлов различается, хотя восстановленные значения и типы совпадают.

**Ограничения сравнения.** У INI нет единого универсального стандарта. `configparser` может обрабатывать ряд конструкций не так, как ручной диалект: например, `[DEFAULT]` — специальная секция настроек по умолчанию для `configparser`, но обычная секция для нашего парсера. Отличается и интерпретация некоторых отступов или заголовков с пробелами. Поэтому доказано совпадение для данного расписания и проверенных случаев, а не для всех существующих вариаций INI.

## Вывод

Библиотечные функции заменяют собственные алгоритмы разборки и сериализации, сокращают объём основного кода и позволяют получать эквивалентные данные при сохранении информации. Ручная реализация полезна для изучения грамматик и принципов конвертации; готовые библиотеки удобнее для прикладной разработки. Различия в кавычках и форматировании YAML не означают различия данных. Для точного сравнения важно сопоставлять восстановленные структуры и учитывать особенности поддерживаемого синтаксиса.
