# ЛР №4, вариант 87 — дополнительное задание №2 (+10%)

## Что требуется

Повторить исходную INI-десериализацию и YAML-сериализацию с готовыми библиотеками, затем сравнить с собственными реализациями и объяснить сходство/различие результатов в отчёте. Регулярные выражения в своём коде не используются.

**Библиотеки:**
- `configparser` — стандартная библиотека Python, для INI.
- `PyYAML` (импорт `yaml`) — внешняя библиотека, для YAML.

Документация: https://docs.python.org/3/library/configparser.html и https://pyyaml.org/wiki/PyYAMLDocumentation

## Как запустить в VS Code на Windows (Python 3.13)

1. Распакуйте папку `lab4_dop2` целиком. Не перемещайте файлы по отдельности.
2. Откройте эту папку в VS Code.
3. Установите PyYAML **для того же Python, которым запускаете main.py**:

   ```powershell
   py -3.13 -m pip install PyYAML
   ```

   Если команда `py` недоступна, попробуйте:

   ```powershell
   python -m pip install PyYAML
   ```

4. Запустите:

   ```powershell
   python main.py
   ```

   Или кнопкой «Запустить файл Python» в VS Code. `main.py` ищет исходный файл рядом с собой, поэтому не важно, какая папка открыта в терминале.

5. Появятся файлы `schedule_manual.yaml` и `schedule_library.yaml`. Программа сравнит словари и YAML-данные.

Проверка на другом файле (путь к INI передаётся как аргумент):

```powershell
python main.py "C:\path\to\other.ini"
```

Необязательные тесты:

```powershell
python test_comparison.py
```

## Файлы

- `main.py` — запускает оба подхода и сравнивает результаты.
- `library_converter.py` — **новая библиотечная реализация** `parse_ini_library()` и `serialize_yaml_library()`.
- `ini_parser.py` — копия самостоятельного парсера из обязательной части, не изменена.
- `yaml_serializer.py` — копия ручной сериализации из доп. №1, не изменена.
- `schedule.ini` — твои 9 занятий.
- `schedule_manual.yaml` — результат ручной сериализации.
- `schedule_library.yaml` — результат PyYAML.
- `test_comparison.py` — необязательные тесты.
- `COMPARISON_REPORT.md` — текст для раздела отчёта.

## Важное отличие

`configparser` и наш самодельный парсер не идентичны для **любого** вообразимого INI: например, `configparser` особым образом обрабатывает секцию `[DEFAULT]`, а ручной парсер считает её обычной. На предоставленном расписании и тестируемых конструкциях результаты совпадают. Эти ограничения нужно честно указать в отчёте.
